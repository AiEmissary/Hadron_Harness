# Hadron tools - revision72

Date: 2026-11-06. The initial tool-development and public-web toolkit is implemented for independent ChatGPT/Codex agent jobs. This is the Hadron tool format and controlled coordinator path; no Graviton custom-tool folders, credentials, browser profiles, caches, trading data or executable dependencies were copied or changed.

## Use it

1. Fully quit Hadron normally and reopen its shortcut so the new server/runtime is loaded. Existing ChatGPT sign-in should persist.
2. Choose Independent jobs, select ChatGPT and a model for either agent, then choose its Tools mode: Text and attached files, Web research, or Create and test tools.
3. Write the task on the left and send it normally. Web research can read supplied public HTTP(S) URLs and follow their links through private per-job navigation history. Search uses a Brave Search API key configured separately in Hadron Settings; reading a supplied URL does not need that key.
4. To create a tool, ask an agent in Create and test tools mode to write and test it. Source is saved as a disabled immutable version. Tool library -> Refresh tools -> Review source shows its JavaScript and input schema. Only the user can enable the reviewed content hash for future jobs. Either agent can then reuse that enabled version.
5. Developers can also use Tool library -> Add a tool. Enter a name, description, JSON input schema and a JavaScript generator function named run(args). Save the disabled version, enter JSON test inputs and run Test this version. Cancel test aborts a pending manual test. Testing does not enable the tool. Updating the same name creates a separate version; the previous enabled version stays active until its replacement is approved.

Example first research task: Read https://example.com and return the page title and source URL. Example builder task: Create a reusable word-count tool with a text input; test empty text, one word and several words. Distinguish successfully executing a test from verifying that every possible input is correct.

## Storage and packaging

Development code/versions/activity live under `Hadron-Harness/custom-tools`. Runtime data is namespaced by an owner hash; each source version has a content hash and definition.json/index.js. Enabled state is a separate user-controlled atomic record. Source creation and enablement use atomic writes/renames; interrupted temporary files cannot become registered versions. Desktop smoke tests instead use their own temporary Hadron profile.

Packaged applications keep the engine and guide in the Hadron program, with writable tool source under that installation's own Hadron profile. This avoids installation-folder write restrictions and protects tools during upgrades. The installer resources include hadron-tools/TOOL_DEVELOPMENT.md. User-generated tool libraries are not automatically added to an installer or uploaded to Git.

The existing inherited Main chat custom-tool loader remains a separate legacy Node-module format in Hadron's own profile. It is not the native Agent A/B tool library, and its settings do not grant tools to Agent A/B. No link points back to installed Graviton's custom-tools directory.

## Execution contract

The official Codex CLI retains its text-only/read-only native sandbox, no native tools and its existing one-request transport guard. A trusted in-process Hadron capability mediates an explicit sequence of text requests and validated tool operations. JSON received from a client or model cannot manufacture that capability. Text-only jobs retain one request. Tool mode allows at most8 model requests per answer,32 host operations per job,12 JavaScript generator steps per invocation and a5-minute deadline. No transport retry or startup replay is added.

Custom JavaScript executes in a fresh QuickJS VM with16 MiB memory and200 ms CPU per step. It has no Node/process/require/filesystem, DOM, cookie store or arbitrary network APIs. It can yield only web_read, web_search, web_navigate, web_back or web_forward, and return JSON. Computation/text/JSON tools need no web calls. Native shell, arbitrary project edits, package installation, signed-in browsing, forms and downloads remain unavailable. Developers should use this explicit generator format; old arbitrary Node tools cannot simply be dropped into this library.

HTTP reading uses checked public DNS addresses pinned into the connection, revalidates redirects and blocks local/private addresses and non-web ports, including Graviton's listener. It sends no browser cookies or account credentials. Page scripts are never evaluated; real HTML parsing extracts bounded text and links. Content/catalog descriptions are untrusted evidence and cannot grant capabilities. Search uses Hadron's own secure Brave key; no global environment-key fallback is used by the native tool session.

Draft tests are scoped to their creating job, or an explicit user-initiated manual test. A model cannot enable/publish its own tool. Enabled definitions are pinned to an exact hash, source changes invalidate the version, and disabling prevents later invocations by an already-open job. A/B histories and navigation stay private. Enabled tool source is intentionally reusable by both agents under the same owner after user approval. Web mode cannot create tools. CPU/host/network limits, owner checks and reserved tool names apply to manual tests too.

## Logs, Stop and restart

The normal automatic Markdown journal records the selected tool mode honestly. Tool activity is visible beside the current agent conversation and saved as flushed bounded status records in the library job-logs folder, without full arguments, source code or page bodies. A torn final activity append is treated as unconfirmed. Restart restores saved source, enablement and conversations, defaults the next message to text mode, and never resumes tool execution or inference. Stop cancels the coordinator, active native generation, pending DNS and web requests. Manual test cancellation closes its request and cancels pending host operations.
