# Two-pane redesign local test build - 10 November 2026

The redesigned desktop route is connected and ready for local user acceptance. The installed application, installer and release source package have NOT been replaced. Real-account use of the new interface still needs acceptance testing.

## Implemented and connected

- Chronological transcript on the left, branch tree on the right, one fixed bottom-left composer in every work type. No third setup pane. Flat filled controls without decorative borders or glow.
- Work type, individual A/B selection, Chat/Agent permissions, provider/model selection, actual account connections and the 1-100 conversation turn limit are in the composer pop-up. Chat/Agent controls Work together too.
- Individual and shared Agent requests use native reading, editing and command tools in the chosen folder. Chat grants reading only. Folder selection does not silently reset permission. Folder authority is never restored from saved history.
- Real file attachments and excerpt handling, provider refresh, project/conversation instructions, saved sidebar chats, previews and old shared/individual/build/continuous histories connect to the new surface.
- Independent A/B chats retain separate drafts, branches and work. Opening saved work observes its native status without starting another request. Uncertain tasks remain fenced rather than being silently duplicated.
- Right-click transcript/tree selections use the native transactional archive: copy/move highlighted portions or multiple nodes, append to an existing chat, create a named chat/project, edit, branch, add notes, inspect information and recover from the 30-day bin. Opening a destination refreshes its saved contents. Selecting A/B on a newly imported unsent chat chooses who continues it without losing the imported context.
- Whole-chat moves through the old sidebar checkpoint drafts and update canonical project ownership. Deleted or edited ancestry is not silently reintroduced through native continuation.
- Help beside the composer describes the new workflow, permissions, branching and transfer options.
- Continuous conversation now stops when one agent proposes a settled conclusion and the other independently confirms that exact proposal. Host-issued per-turn markers prevent ordinary agreement or stale tokens from being treated as consensus. A new user instruction invalidates pending confirmation. The final saved reply says that consensus was reached; no extra button was added. Continuous conversation counts visible reply attempts separately from internal memory summaries. Choosing 100 permits 100 conversation turns; summaries require additional internal model requests. Temporary failures remain bounded and ambiguous failures are not blindly retried.
