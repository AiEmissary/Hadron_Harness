# Private storage policy - revision89

ExecutionStartup pins the actual profile directory device/inode once per host. PrivateProfilePaths checks the pinned root and existing ancestors/leaves for every participating operation. Escapes, alternate streams, linked/junction directories, non-regular file targets and hard-linked file leaves are refused. Reinitializing the same path cannot silently adopt a replacement root. Missing descendants may be created only under that checked root. A check is host storage validation, never a model/project grant; it does not certify unrelated external filesystem races or all other stores.

Configured desktop, standalone and utility hosts use this policy. Unconfigured legacy test/library hosts retain prior root resolution but cannot acquire project execution authority. Native source grants and canonical project writes remain separate capabilities.

## Theme maintenance

Theme initialization/list/read/save/delete stay in the pinned .ygg/custom-themes directory. A late external environment override fails before mutation. Template links/hard links are refused. Copy uses exclusive creation and revalidates raced targets. Saves open without truncation, verify actual handle/name/links, and then write. Normal theme maintenance does not make a project session look like unresolved arbitrary legacy execution.

## Automatic job logs

AgentJobJournal validates the configured private destination on every location/checkpoint/read, including unchanged cached snapshots. A linked log folder or hard-linked log file is refused before it can redirect access to a project. The bounded reader opens a descriptor, checks actual identity/links/size, reads at most2 MiB plus one byte, rechecks identity/timestamps and rejects changed or invalid UTF-8 data. This applies to project, individual A/B and collaboration stage logs.

Checkpoints use exclusive temporary files, fsync before rename, checked paths and identity-bound cleanup. A temporary file which was not successfully created/identified by this attempt is not deleted on failure. In-memory deduplication is not proof the Markdown file survived: the durable checkpoint marker is checked, and a removed record is recreated with full current notes. An invalid/oversized durable record fails instead of silently confirming an unchanged memory cache. Atomic private log writes are not canonical project edits or proof of successful tests.

## Advanced app-registration connection record and mutation lease

HadronChatgptStore retains its existing encrypted format and safeStorage cipher. This is the advanced app-registration flow; it does not cover the separate official Codex subscription credential directory. The constructor pins the actual profile root and participating operations also check the host-wide configured profile when available. A different configured destination, replaced root, linked account directory or hard-linked leaf is refused. Reads open a bounded descriptor, verify identity/links/size and unchanged timestamps before decryption. Corrupt or oversized records remain untouched. Writes check targets, create exclusive identified temporaries, sync before rename and clean up only their own temporary.

The accompanying mutation lease checks pinned storage before creating the account directory/lock and before cleanup. It verifies actual lock identity before running provider work, bounds cleanup reads and preserves ambiguous, changed, linked or replaced locks. No PID/age-based lock stealing is introduced. Successful operations release only the same identified lock; interrupted or unverifiable storage still requires intervention. Private account maintenance does not grant project execution or release its scope. These checks do not claim protection against unrelated external filesystem races.
