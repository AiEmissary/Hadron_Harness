# Folder groups and serialized context admission — 22 November 2026

The current single-agent continuation failed after eight recorded operations with `Hadron job context exceeded limit`. The ChatGPT adapter refused the fully serialized request at 131,072 characters before provider dispatch. The tool loop estimated its own packet but did not account for the adapter's extra JSON escaping and outer worker instructions. This was a local admission failure; it is not evidence of exhausted provider allowance.

The adapter now supplies a request-fit predicate to the tool loop. The predicate measures the same single-user-message serialization and combined system prompt as actual dispatch. The loop shortens older evidence before dispatch when either its token estimate or the adapter's serialized limit is exceeded. Host formatting instructions are included in the estimate. The final adapter guard remains as defence in depth and reports a classified context error so the existing bounded text-only retry can compact it. Completed tools are not replayed. The original task, recent evidence, operation references and incomplete/completion distinction remain. This is bounded compaction, not a semantic summary of every old chat turn, and provider/time/request limits still apply.

The earlier approved folder changes are included: the paperclip menu can select several working folders together, add to the selection, replace it, remove one, or remove all. Native grants authorize each root separately; no common-parent grant is created. Tools use optional folder aliases (`folder1`, `folder2`, etc.) with paths relative to the chosen root. File and command operations use that selected working directory. Read-only reviews and continuous conversation retain their existing permissions. Selecting folders does not change Chat/Agent permission or provider/model choices.

Native bookmarks preserve the full selection and directory identities across restart. The saved chat records explicit detachment and the bookmark slot last selected, without storing live capability IDs. Removing the last folder cannot fall back to an older mode selection. Remaining selected roots are revalidated before a new grant; an unavailable removed root does not prevent clearing the selection. Cancelling or rejecting a folder replacement preserves the previous grant. Changes to folders are blocked while the affected agent is working. Whole drives, credential directories and protected application/account roots remain unavailable as working roots, following the user's choice of several specific folders. Existing local path-level guards are retained as additional defence.
