# Continuous debate roles, source checks and one final pass — 27 November 2026

Continuous conversation now gives A the proposer role and B the strongest defensible opposing position, unless the user assigns different positions. The critic must use counterevidence and alternatives without inventing disagreement or defending false claims. Both agents are instructed to separate facts, inference and opinion, prefer primary sources, cite consulted URLs or file/page/line references, and acknowledge failed or missing checks.

Every conversation reply's host tool session now requires an actual relevant source-check attempt. Web search/read, attached-document search/read and selected-folder search/read count; listing custom tools or merely promising to check does not. The host issues its existing correction when an agent tries to answer without attempting evidence. Failed tool calls can establish that checking was unavailable, but do not establish verification. Public web access never authorizes sending private project/document contents to search. Ordinary turns have eight host requests and document turns retain their larger existing budget. Internal memory summaries remain tool-free and are not counted as conversation replies. This enforces attempts, not the truth of every interpretation or quality of every citation.

Current participant identity is host supplied with provider and model. Each new transcript entry carries its recorded source identity; saved continuations retain those identities even if A/B are later assigned different providers. Historical turns without recorded provenance are marked unknown rather than attributed to the new model. Memory instructions preserve identity and citations. Cross-mode handover excerpts also include recorded provider/model labels; a combined reply's recorded model is labelled as its synthesis identity, not as the identity of both contributors.

A proposed settled conclusion opens one final checking reply by the peer. Clear unqualified agreement openings also open a checking pass, without being treated as proof of consensus. The scheduler pauses after that reply: explicit valid confirmation produces consensus_reached; otherwise final_check_complete retains the peer's unresolved concerns and explicitly says agreement was not confirmed. Scheduled memory compaction cannot consume the checking reply. New user instructions arriving during checking invalidate the stop so the new request can be addressed. Quoted, stale and partial agreement is not consensus. Existing turn/time budgets, cancellation, provider failures and broader repetition guards still apply; the phrase fallback is deliberately conservative, not a semantic detector for every possible wording of agreement. Paused discussions can be explicitly continued by the user.
