# Routine helpers - implemented in revision 99

The main A/B workflows now admit bounded same-provider helpers through the trusted host broker. Automatic lightweight helpers is enabled by default and can be disabled above the middle tree. Known available tiers are preferred in order: OpenAI nano, mini, Luna; Claude Haiku. Unknown models never cause automatic premium promotion or provider switching. This is a known tier policy, not a live price quotation.

At most two helpers per owner/job/agent across stages, one level only, 120 seconds each, 24,000 supplied-context characters and 6,000 output characters. Actual detached child identity, owner/workspace, parent run, provider/model and completed response are checked. Helpers receive no native tools, write/test ability or further delegation. helper_read calls only the parent's existing project_read grant. Project proposal helpers can analyse frozen supplied context; no new folder authority is invented.

SQLite records bind children to parent jobs/runs. Separate Markdown checkpoints and visible parent-linked activity/history are retained. Parent cancellation aborts and joins children. Restart marks unfinished helpers interrupted and never redispatches them. Disabling the preference prevents new requests; stopping the parent cancels an already-running helper. Automatic conversation remains text only. Automatic project repair rounds disable helpers to preserve the original approval budget.

Validation: six service tests passed (tier selection, ownership, budget, structured output, grants, cancellation/join, interrupted restart). Disposable real main/preload/server/run-service UI fixture created an OpenAI lightweight child and a Claude Haiku child, returned the actual persisted child output to the corresponding parent, and verified history. Provider text in the fixture is synthetic; real API billing/pricing and simultaneous paid helper calls were not exercised. Further configurable budgets, custom helper roles and extended helper trees are deferred.
