# Revision 103 - selected-folder search and lightweight scanning helpers

Build a project now defaults to folder exploration. Choose project folder grants access; individual source picks are optional hints. Agent A may use project_list, project_search (recursive literal content or filename matching) and project_read, then returns the existing structured proposal. Read files are frozen in the host database with exact original hashes before they can be replaced; Agent B receives the frozen context and exact before/after review. Search hits alone grant no replacement authority. No directory copies, shell access or automatic writes were added.

The trusted existing helper broker now supports helper_search: bounded granted search results are analysed by a known lightweight model from the parent's own provider. helper_read can summarise relevant file ranges with the same project grant. Two helpers for Agent A across the task, one level, no child file/tool authority or nested delegation. Global opt-out and same-provider admission remain enforced. B remains the exact-snapshot reviewer. Folder mode permits up to 18 parent proposal/review requests plus two helper requests; ordinary automatic build/test/fix repairs disable exploration and helpers to retain their existing approved budget.

Each search is bounded to 2000 entries, 100 content files, 8 MiB and 50 matches with a 12k-character result budget. Dependencies, common generated folders, links and common credential paths are skipped. Searches report truncation/skips; absence of a hit is not proof of absence. Files can be read in line ranges; frozen build context remains at most 20 files / 128 KiB, preventing wholesale long-file loading into prompts. Large projects need focused goals/subfolder searches. Permissions expire on restart; no paid work replays automatically.

Persisted folder operation metadata is visible in Project folder activity and job logs. Relevant files found is shown separately from manual picks. Help now describes the folder workflow.
