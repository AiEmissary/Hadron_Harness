# Revision 111 - startup checkpoints and truthful saved-session status (8 November 2026)

Windows preview 0.4.11 fixes the Automatic conversation saved dropdown retaining an old running status after live polling has paused or finished the selected session. The desktop fixture checks that the saved option agrees with the actual paused state.

A lightweight diagnostic bootstrap now runs before the normal host bootstrap. In an explicit private --hadron-diagnose profile only, it records bounded, atomic startup checkpoints with a unique invocation ID: bootstrap/profile/main, instance lock, app ready, server ready, window/renderer load and terminal diagnostic state. Known startup/renderer failures and an early normal quit produce a matching failure report. Normal application launches do not enable this recorder or change their profile.

Abrupt Electron exits can bypass JavaScript exit/quit callbacks: a native test establishes this. The durable last checkpoint still remains, and the diagnostic launchers preserve the exit code and last stage when a complete report is absent. A fresh result must match the invocation trace; old success reports are not sufficient. Portable ZIPs now include startup-trace.json alongside the existing allowlisted reports/screenshots, never an account store, normal chat database or raw process log. This improves future diagnosis; it does not establish or fix the cause of the earlier unexplained startup exit or old NSIS crashes.

The Windows worker build now reuses an existing binary only when source, compiler, build recipe and binary hashes all match its manifest. This avoids rewriting an unchanged executable while it is in use. Changed builds still require compilation and never kill an active worker to gain access. The existing manifest schema stays compatible with the protected runtime. Actual Windows worker containment tests passed after the change.

# Automatic two-agent conversation - revision93

Automatic conversation is a separate opt-in workspace mode. The left pane holds the shared transcript, the centre shows ordered turn cards, and the right contains the shared goal, A/B ChatGPT model choices, budgets and controls. The same connected subscription can serve both agents. Their completed turns are routed by Hadron; neither receives the other's account credentials.

Start exchanges turns without another Send after each response. Default:20 turns and600 seconds; configurable2–100 turns and10–3600 seconds. Pause finishes the current turn and schedules no successor. Stop aborts and joins the current actual worker. A message to both agents is saved and included at the next turn boundary. Resume is explicit and shows that extending an exhausted budget adds up to20 turns, with100 total maximum. Exact repeated replies and a64 KiB context limit pause the conversation. A per-turn deadline also applies. There is no silent compaction or fabricated token/cost report.

The dedicated durable database records the reserved ordinal and frozen prompt before dispatch, binds the actual run/handle/stream before a provider request, and saves the terminal response before scheduling the successor. Duplicate Start and message IDs are idempotent; mismatched identities and foreign owners are refused. No automatic retry or inference occurs on cold reopen. Interrupted sessions require recovery; historical sessions are read-only and cannot adopt an old worker. Continuing a historical conversation through a fresh explicit branch is still pending.

Each agent gets an automatic Markdown continuity log at preparation, run binding and completion. The database preserves the complete ordered transcript. Login/logout and Quit close automatic admission and cancel active work. This mode has no tools, project files, shell, delegation or editing. It does not replace independent proposals/review or grant project-building permissions. Claude integration for this mode remains pending.

The desktop fixture exchanges40 alternating synthetic turns, injects a user message at a boundary, exercises Pause/Stop, creates another saved conversation and reopens it without inference. The real main/preload/server/provider-admission/storage/UI code is exercised; generation is synthetic and consumes no real subscription requests. Core tests separately cover twenty turns, budgets, duplicate requests, ownership, cold recovery and unknown termination.

Chess can demonstrate verbal turn exchange. Legal chess requires a deterministic board/rules validator; no such validator is implemented or claimed here.
